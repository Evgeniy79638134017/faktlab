# Публикация faktlab.ru

Сайт статический: HTML, CSS, JS без сборки. Публикуется на GitHub Pages, домен от Рег.ру.

## 1. Репозиторий

Локальный git уже создан, история есть. Осталось создать удалённый и запушить:

```bash
gh repo create faktlab --public --source=. --remote=origin --push
```

Если `gh` не установлен — создать репозиторий вручную на github.com и выполнить:

```bash
git remote add origin https://github.com/<аккаунт>/faktlab.git
git branch -M main
git push -u origin main
```

Токен для доступа лежит в `Главный\.telegram_config\.env`, строка `GH_PAT`.

## 2. Включить Pages

В настройках репозитория: **Settings → Pages → Source: Deploy from a branch → main / (root)**.
В поле **Custom domain** вписать `faktlab.ru`. Файл `CNAME` в репозитории уже есть, GitHub подхватит его сам.

## 3. DNS у Рег.ру

В карточке домена → «DNS-серверы и управление зоной». Домен должен стоять на DNS Рег.ру
(`ns1.reg.ru` / `ns2.reg.ru`) — иначе редактор зоны не откроется.

### 3.1. Убрать записи парковки

Удалить все существующие записи типа A и AAAA для `@` и для `www` — они ведут на страницу-заглушку
регистратора (`95.163.244.138`). Пока они на месте, новые записи будут конфликтовать со старыми.

### 3.2. Голый домен — четыре записи A

Для имени `@` (это и есть `faktlab.ru` без приставок) добавить четыре записи A:

```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

Четыре, а не одна: это разные площадки GitHub. Если одна недоступна, браузер берёт следующую.

### 3.3. www — одна запись CNAME

CNAME — это псевдоним: «имя `www.faktlab.ru` означает то же, что вот этот чужой адрес». Сам IP при
этом не указывается, GitHub меняет его у себя, а домен продолжает работать.

В форме добавления записи в Рег.ру:

| Поле | Что вписать |
|---|---|
| Тип записи | `CNAME` |
| Поддомен (Subdomain) | `www` |
| Канонический адрес (Canonical name) | `evgeniy79638134017.github.io.` |
| TTL | оставить по умолчанию (3600) |

Три вещи, на которых обычно ошибаются:

1. **Точка в конце обязательна** — `evgeniy79638134017.github.io.` Точка означает «полное имя от корня».
   Без неё Рег.ру достроит имя от своей зоны и получится `evgeniy79638134017.github.io.faktlab.ru` —
   такого адреса не существует, сайт не откроется. Если поле не принимает точку и подставляет её само —
   значит, интерфейс уже работает с полными именами, вписать без точки.
2. **Только имя сервера, без репозитория и без протокола.** Не `https://…`, не
   `evgeniy79638134017.github.io/faktlab`, не имя репозитория вообще. В записи CNAME может стоять только
   доменное имя.
3. **Логин пишется строчными буквами.** GitHub отдаёт страницы по адресу в нижнем регистре, хотя сам
   аккаунт записан как `Evgeniy79638134017`.

Ещё одно ограничение: у имени `www` не должно остаться других записей, кроме этой CNAME. Стандарт DNS
не допускает CNAME вместе с A или AAAA на одном имени — часть провайдеров такую зону просто не примет.

Обратный вариант (CNAME для голого домена вместо четырёх A) невозможен: на корне зоны уже лежат
служебные записи SOA и NS, а CNAME по стандарту исключает соседство с чем бы то ни было.

### 3.4. Что должно получиться

```
@      A       185.199.108.153
@      A       185.199.109.153
@      A       185.199.110.153
@      A       185.199.111.153
www    CNAME   evgeniy79638134017.github.io.
```

Записи MX, TXT и прочие, если они есть, не трогать — они к сайту отношения не имеют.

### 3.5. Проверка

Изменения расходятся от получаса до нескольких часов (иногда до суток — зависит от TTL старых записей).

```bash
nslookup faktlab.ru 8.8.8.8
```

```bash
nslookup -type=CNAME www.faktlab.ru 8.8.8.8
```

Первая команда должна показать четыре адреса `185.199.*`, вторая — `evgeniy79638134017.github.io`.
Пока видны старые значения — ждать, повторных действий не требуется.

### 3.6. Если CNAME недоступен

Некоторые панели не дают завести CNAME для `www`. Тогда на `www` вешаются те же четыре записи A, что и
на голый домен. Работать будет, но при смене адресов GitHub зону придётся править руками — поэтому
это запасной вариант, не основной.

### 3.7. Куда в итоге ведёт www

В репозитории лежит файл `CNAME` со строкой `faktlab.ru`. GitHub считает основным именно этот адрес и
переадресует `www.faktlab.ru` на `faktlab.ru` автоматически. Сертификат выпускается на оба имени, так
что посетитель попадёт на сайт, набрав любой вариант.

## 4. Сертификат

После того как DNS разошлись, в **Settings → Pages** дождаться выпуска сертификата (обычно 10–30 минут) и включить **Enforce HTTPS**.

## 5. Проверка после публикации

- открыть `https://faktlab.ru` и `https://faktlab.ru/cases.html`;
- отправить тестовую заявку — она должна прийти в Telegram. Если не приходит, смотреть консоль браузера: ошибка про источник запроса означает, что домен не совпал со списком в `worker/worker.js`;
- проверить страницы политики, согласия и условий;
- убедиться, что `https://faktlab.ru/sitemap.xml` и `robots.txt` открываются.

## Что не выложено в репозиторий

Служебные файлы исключены через `.gitignore`: состояние задачи, промпты визуала, инструкции по сборке, резервные копии. Секретов в репозитории нет — токен бота и chat_id хранятся в секретах Cloudflare.
